# 07: 标签分页

**What to build:** 管理页的「标签」分页：一张表格列出所有标签（名称、句数，0 句的也列出）。第一行是新增：打名称按 Enter 就建立，可以先建一个还没有名句用到的标签；名称与已有标签只差大小写时不会多出一个，而是标示出已有的那一列。点名称就地改名，Enter 储存、Esc 取消；只改大小写就是改写法；改成另一个已有标签的名称（忽略大小写）就是合并——按钮先变成「确定合并？」并说明「『工作』的 3 句会并入『职场』」，再按一次才执行，同时有两个标签的名句只留一个。0 句的标签有「删除」，按两次确认；有名句的标签没有删除按钮。见 [spec](../spec.md)「API」与 GLOSSARY.md 的「合并」。

**Blocked by:** 02, 03, 06

**Status:** ready-for-agent

- [ ] API：新增标签（已有 → 200 回传已有的，否则 201）、改名（与另一个标签冲突且没要求合并 → 409 并带出冲突的标签；要求合并 → 合并并删除原标签）、删除（0 句 204、有名句 409、不存在 404）；都在 `/api/admin/*` 底下，没通过 Access 回 403
- [ ] 合并在同一个 transaction 完成；两个标签都有的名句合并后只有一笔关联
- [ ] 分页列出现「标签」，有自己的网址，重新整理后停在这个分页
- [ ] 表格显示名称与句数（含 0 句）；新增、同名标示、就地改名、只改大小写、合并确认、删除 0 句都可用
- [ ] 操作后，名句分页的标签、侧栏、句数与阅览页都反映结果
- [ ] API 测试脚本补上上述案例并全部通过
